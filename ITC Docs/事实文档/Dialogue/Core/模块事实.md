# Dialogue Core 模块事实

最后更新时间：2026-04-01（Asia/Shanghai）

## 1. 模块职责

- 提供统一对话面板 `ITCDialoguePanel`。
- 将 Yarn 命令桥接到视觉切换、小游戏流程和场景切换。
- 管理文本呈现、继续/快进输入、文本事件转发。
- 为“场景直载版签约链路”提供对话命令桥，而不是继续依赖动态异步开面板。

## 3. 场景与生命周期事实

- `Assets/Scenes/DialogueScene.unity` 当前是签约对话叠加场景。
- `DialogueScene` 内已承载 `SignUI` 与 `EventSystem`，不再是旧的空壳跳板场景。
- `DialogueSceneFlowLauncher` 当前职责已经简化：
  - 不再执行 `ResKit.InitAsync()`
  - 不再通过 `UIKit.OpenPanelAsync` 打开 `ITCDialoguePanel`
  - 仅在场景内查找 `DialogueRunner`，按配置启动 `startNode`
- 当前正式链路中，`ITCDialoguePanel` 作为场景内组件存在，不再要求通过 `dialogue_ui` 资产包动态实例化。

## 4. ITCDialoguePanel 命令桥接事实

### 4.1 视觉与场景命令

- `itc_bg`：切背景图。
- `itc_npc_main` / `itc_npc_avatar` / `itc_pc_avatar`：切换角色图。
- `itc_npc_main_hide` / `itc_npc_avatar_hide` / `itc_pc_avatar_hide`：隐藏对应图层。
- `itc_load_scene`：仍通过 `SceneManager.LoadSceneAsync` 切场景。

### 4.2 小游戏命令

- `itc_doc_review`
- `itc_rune_typing`
- `itc_rune_verify`
- `itc_stamp_select`
- `itc_soul_collect`
- `itc_bean_sell`
- `itc_settlement`

当前统一模式（代码实装）：
- 先读 Yarn 变量，发送 BeginCommand。
- 通过 `SignMiniGameSceneHost` 解析场景内小游戏宿主。
- 调用宿主的 `OpenXxx(...)` / `CloseXxx()` 打开或关闭已在叠加场景中落地的 `UIPanel` 实例。
- 监听 Panel `OnCompleted` 回调发送 SubmitCommand。
- 超时或宿主缺失时触发 fallback payload，避免 Yarn 主流程卡死。
- 将 `SignMiniGameFlowStateModel` 中结果回写 Yarn 变量。

## 5. 文本呈现与输入事实

- `TALinePresenter`
  - 继承 `DialoguePresenterBase`
  - 支持 `TextAnimator + Typewriter`
  - 支持快进时禁用渐入特效优化
  - 支持“前置管道标签（`|tag|`）”解析，并注入 Text Animator 默认特效标签
  - 在 Sign 路由模式下，可关闭 legacy 文本层并把行路由到 `SignDialogueRuntimeFacade`
- `DialogueContinueHandler`
  - 支持鼠标、键盘、按钮触发继续
  - 支持 Ctrl 快进节奏
  - 对 Sign 运行时的 continue block 状态做阻塞判定
- `TADialogueEvents`
  - 桥接 Typewriter 与 DialogueRunner 的事件到 UnityEvent
  - 提供 Skip 期间事件过滤

## 6. 视觉资源解析事实

- `DialogueVisualCatalog` 当前映射不再只服务 AB 路径：
  - `DialogueSpriteRef` 已支持 `directSprite`
  - `DialogueVisualCatalog` 已支持 `missingSprite`
- `DialogueSpriteProvider` 当前加载策略为：
  - 优先 `directSprite`
  - 其次缓存
  - Editor Simulation 下可走 `editorAssetPath`
  - 否则才通过 ResKit 异步加载 AssetBundle，再取 Sprite/SubSprite
- `ITCDialoguePanel.LoadMissingSpriteAsync()` 也已优先使用 catalog 中直接挂载的 `missingSprite`。

## 7. 关键变量读写事实（核心）

- 读：`$Route_CurrentClient`、`$DAY`、`$satisfaction`、`$Sign_mistake`、`$Route_BeanSoldCount`、`$Route_RuneVerifyResult`、`$Route_RuneVerifyDebuff`、`$money`、`$Nmber_of_sign_mistake`、`$Global_sign_mistake`
- 写：`$Route_*` 各玩法结果，以及 `$satisfaction`、`$Sign_mistake`、资金/失误累计变量

## 8. 当前与旧链路的差异事实

- 旧事实中的 `UIKit.OpenPanelAsync<...>(assetBundleName: "sign_minigame_ui")` 不再是当前小游戏主路径。
- 旧事实中的 `DialogueSceneFlowLauncher -> ResKit.InitAsync() -> Open ITCDialoguePanel` 已不再成立。
- 当前 Core 模块更偏向“场景内命令桥 + 场景内视觉资源解析 + 场景内小游戏宿主管理”。
