# Dialogue Sign 子模块事实

最后更新时间：2026-04-01（Asia/Shanghai）

## 1. 子模块职责

- 为签约流程提供正式的模块化对话运行时。
- 把签约主内容、对话 UI、签约小游戏 UI 拆到不同场景承载。
- 将对话层从“SignScene 内完整承载全部 UI”调整为“SignScene 只放主体，DialogueScene 叠加承载对话”。

## 3. 当前正式场景拆分事实

### 3.1 SignScene（主体承载）

- `Assets/Scenes/SignScene.unity` 当前是签约主体内容承载场景。
- 当前根对象已收缩为：
  - `ITC Main Camera`
  - `SignSceneOverlayLoader`
- `SignScene` 不再直接承载完整 `SignUI` 对话系统。

### 3.2 DialogueScene（对话叠加）

- `Assets/Scenes/DialogueScene.unity` 当前是签约对话叠加场景。
- `SignUI` 已迁入 `DialogueScene`。
- `EventSystem` 也已迁入 `DialogueScene`。
- `DialogueScene` 中承载正式 `SignDialogueSceneBootstrap`、`SignSceneDialogueLauncher`、`ITCDialoguePanel` 等运行时组件。

### 3.3 SignMiniGameOverlayScene（小游戏叠加）

- `Assets/Scenes/SignMiniGameOverlayScene.unity` 当前是签约小游戏叠加场景。
- 当前已存在 `SignMiniGameOverlayRoot`。
- 该根对象上挂有 `SignMiniGameSceneHost`。
- 七个签约小游戏 panel prefab 已直接实例化进该场景，供宿主脚本直接开关与调参。

## 4. 当前叠场景入口事实

- `SignSceneOverlayLoader`
  - 位于 `SignScene`
  - 按代码负责在运行时把 `DialogueScene` 与 `SignMiniGameOverlayScene` 作为 additive scene 拉起
  - 当前支持按场景名或 build index 解析场景
- `SignRuntimeSceneBootstrap`
  - 是脱离场景对象生命周期的全局兜底脚本
  - 通过 `RuntimeInitializeOnLoadMethod` 注册运行时 sceneLoaded 监听
  - 按代码负责在 `SignScene` / `DialogueScene` 进入后再次确保签约链叠加场景已准备
- `SignSceneDialogueLauncher`
  - 当前不再初始化 ResKit / UIKit
  - 启动 `DialogueRunner` 前会再次确认 `requiredOverlaySceneNames` 中的叠加场景已加载
  - 默认要求 `SignMiniGameOverlayScene`

## 5. 正式运行时核心事实

### 5.1 Bootstrap / Facade

- `SignDialogueSceneBootstrap`
  - 激活 `签约特制对话系统`
  - 解析 `对话框前置遮罩 / 对话框后置遮罩 / 玩家框遮罩`
  - 把场景中的 `对话框前置 / 对话框后置 / 玩家框` 作为运行时模板
  - 禁用 legacy `OptionsPresenter`
  - 首帧关闭场景内 legacy `TextAnimator_TMP / TypewriterComponent`
  - 切换为 `SignDialogueOptionsPresenter`
  - 重排 `DialogueRunner.DialoguePresenters`
  - 关闭 `allowOptionFallthrough`
- `SignDialogueRuntimeFacade`
  - 作为 `TALinePresenter` 与 `DialogueContinueHandler` 的 Sign 路由桥接入口
  - 提供 `RouteLine(...)`
  - 提供继续输入阻塞状态
  - 提供 legacy 文本层抑制状态

### 5.2 NPC / 玩家 / 选项

- `SignDialogueNpcTrack`
  - `对话框前置` 承载 NPC 最新一句
  - `对话框后置` 承载 NPC 上一句或历史浏览结果
- `SignDialogueHistoryBrowser`
  - 仅在 `对话框后置遮罩` 内处理滚轮历史浏览
- `SignDialoguePlayerTrack`
  - 玩家对白/心理活动只保留当前玩家框实例
- `SignDialogueOptionsPresenter`
  - 选项进入玩家框语义
  - 优先复用模板内已有的 `玩家框选项` 容器

### 5.3 命令与小游戏桥接

- `SignDialogueCommandBridge` 当前仍注册：
  - `itc_sign_npc_enter`
  - `itc_sign_npc_exit`
  - `itc_sign_role`
- 正式小游戏命令统一仍由 `ITCDialoguePanel` 注册并执行：
  - `itc_doc_review`
  - `itc_rune_typing`
  - `itc_rune_verify`
  - `itc_stamp_select`
  - `itc_soul_collect`
  - `itc_bean_sell`
  - `itc_settlement`
- 这些命令当前已经改为操作 `SignMiniGameSceneHost` 管理的场景内 panel，而不是异步打开资源包里的 panel 资产。

## 6. 与 Core 模块的耦合事实

- `TALinePresenter`
  - 优先路由到 `SignDialogueRuntimeFacade`
  - 若新 facade 不可用，则 fallback 到 Legacy `SignDialogueSlotRuntime`
- `DialogueContinueHandler`
  - 优先读取 `SignDialogueRuntimeFacade.IsContinueInputBlocked`
  - 若新 facade 不可用，则 fallback 到 Legacy `SignDialogueSlotRuntime`
- `ITCDialoguePanel`
  - 仍承担背景、立绘、头像、小游戏命令注册
  - 当前在 `DialogueScene` 内作为场景组件存在
  - 当前不再要求通过 `dialogue_ui` 资产包动态打开

## 7. 旧发布链与兼容层事实

- `Assets/Editor/SignScenePublisher.cs` 仍存在于仓库中，属于旧的正式场景发布链。
- 当前实际交付结构已经不再是“完整 SignUI 直接发布到 `SignScene`”这一种单场景形式。
- `Assets/Scripts/Sign/Legacy/**` 兼容层仍保留给旧场景、旧预制体或历史交互控件使用，但不是本次重构后的主扩展方向。
