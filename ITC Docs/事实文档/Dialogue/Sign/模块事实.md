# Dialogue Sign 子模块事实

最后更新时间：2026-03-22（Asia/Shanghai）

## 1. 子模块职责

- 为签约场景提供正式的模块化对话运行时：
  - NPC 前置最新句
  - NPC 后置上一句/历史浏览
  - 玩家对白/心理活动/选项统一落到玩家框语义
- 承担签约场景生产发布链：
  - 测试源场景 `Assets/Tests/Test scene/TestScene_sign UI test.unity`
  - 正式场景 `Assets/Scenes/SignScene.unity`
- 保留旧 `SignDialogueSlotRuntime` 作为兼容层，仅服务旧场景/旧预制体。

## 3. 正式场景与发布链事实

### 3.1 场景来源与替代关系

- 正式 `Assets/Scenes/SignScene.unity` 已由 `Assets/Tests/Test scene/TestScene_sign UI test.unity` 发布生成并替代原壳场景。
- 正式场景根对象为 `SignUI`，不再使用旧的 `DialogueSceneFlowLauncher` 空壳入口。

### 3.2 发布器行为

- `SignScenePublisher` 菜单路径：`Tools/ITC/Sign/Publish Production Sign Scene`
- 发布器会从测试源场景读取并生成正式 `SignScene`。
- 发布器会确保：
  - `SignUI` 上存在 `SignDialogueSceneBootstrap`
  - `SignUI` 上存在 `SignSceneDialogueLauncher`
  - `DialogueRunner` 使用 `Assets/Doc/ITC Doc/dialogue/ITC_YarnWorkSpace/ITC_YARN_Project.yarnproject`
  - 正式启动节点为 `Sign_Day1_Start`
  - `SignDialogueSceneBootstrap.ensureDialogueStarts = false`
- 正式场景里的 `签约特制对话系统` 根对象挂有 `ITCDialoguePanel`，用于注册 `itc_bg / itc_npc_main / itc_npc_avatar / itc_pc_avatar` 等全局对话命令。

### 3.3 AB / ResKit 事实

- `Assets/Editor/ITCDialogueResKitBuildTools.cs` 仍负责现有对话资源的 AB 标签和 WebGL ResKit 构建。
- `dialogue_ui` 现仍指向 `Assets/Prefabs/UI/ITC DialogueSystem.prefab`，用于旧对话 UI 打包链。
- 当前正式 `SignScene` 为场景内直载 `SignUI`，不再依赖 `UIKit.OpenPanelAsync(... dialogue_ui / ITC DialogueSystem)` 作为入口。

## 4. 正式运行时核心事实

### 4.1 Bootstrap / Facade

- `SignDialogueSceneBootstrap`
  - 激活 `签约特制对话系统`
  - 解析 `对话框前置遮罩 / 对话框后置遮罩 / 玩家框遮罩`
  - 把场景中的 `对话框前置 / 对话框后置 / 玩家框` 作为运行时模板
  - 禁用 legacy `OptionsPresenter`
  - 切换为 `SignDialogueOptionsPresenter`
  - 重排 `DialogueRunner.DialoguePresenters`
  - 关闭 `allowOptionFallthrough`
- `SignDialogueRuntimeFacade`
  - 作为 `TALinePresenter` 与 `DialogueContinueHandler` 的新桥接入口
  - 提供 `RouteLine(...)`
  - 提供继续输入阻塞状态
  - 提供 legacy 文本层抑制状态

### 4.2 NPC / 玩家 / 选项

- `SignDialogueNpcTrack`
  - `对话框前置` 承载 NPC 最新一句
  - `对话框后置` 承载 NPC 上一句或历史浏览结果
  - NPC 每句都实例化独立面板，不复用旧实例
  - NPC 切换时清空上一 NPC 的历史与显示实例
- `SignDialogueHistoryBrowser`
  - 仅在 `对话框后置遮罩` 内处理滚轮历史浏览
  - 鼠标移出后回到默认上一句
- `SignDialoguePlayerTrack`
  - 玩家对白/心理活动只保留当前玩家框实例
  - 不保留玩家历史
- `SignDialogueOptionsPresenter`
  - 选项进入玩家框语义
  - 运行时优先使用玩家框模板内已有的 `玩家框选项` 容器
  - 若模板未提供，则创建运行时容器承载按钮

### 4.3 面板与动画

- `SignDialoguePanelInstance`
  - 直接写入 prefab 内嵌 TMP 文本
  - 解析并调用名为 `弹出` 与 `回缩` 的 `DOTweenAnimation`
  - 回缩结束后销毁实例
- `SignDialoguePanelFactory`
  - 负责按模板实例化前置/后置/玩家框
  - 负责挂接到对应遮罩
  - 负责复制文本与返回实例控制器

### 4.4 命令与小游戏占位

- `SignDialogueCommandBridge` 注册：
  - `itc_sign_npc_enter`
  - `itc_sign_npc_exit`
  - `itc_sign_role`
  - `itc_sign_minigame`
- `SignDialoguePlaceholderMinigameBridge`
  - 当前显式支持 `doc_review` 与 `rune`
  - 其余 token 走统一占位显示
  - 占位期间继续输入会被阻塞

### 4.5 正式场景启动器

- `SignSceneDialogueLauncher`
  - 负责正式 `SignScene` 自动启动 `DialogueRunner`
  - 启动前可显式覆盖 `YarnProject` 与 `startNode`
  - 运行时以 `DialogueRunner.IsDialogueRunning` 为闸门
  - 额外带有“前 10 帧兜底启动”逻辑，用于编辑器关闭 scene/domain reload 时保持验证行为稳定

## 5. 与 Core 模块的耦合事实

- `TALinePresenter`
  - 优先路由到 `SignDialogueRuntimeFacade`
  - 若新 facade 不可用，则 fallback 到 Legacy `SignDialogueSlotRuntime`
- `DialogueContinueHandler`
  - 优先读取 `SignDialogueRuntimeFacade.IsContinueInputBlocked`
  - 若新 facade 不可用，则 fallback 到 Legacy `SignDialogueSlotRuntime`
- `ITCDialoguePanel`
  - 仍承担背景、立绘、头像、小游戏命令注册
  - 在正式 `SignScene` 中作为场景内命令桥存在，不再要求通过 UIKit 打开

## 6. Legacy 兼容层事实

- `Assets/Scripts/Sign/Legacy/SignDialogueSlotRuntime.cs`
  - 仍保留给旧签约场景与旧预制体使用
  - 当前不再作为正式 SignScene 的主实现继续扩展
- `Assets/Scripts/Sign/Legacy/SignCtrlHoverDriver.cs`
  - 仍被 `Assets/Prefabs/UI/Sign/*.prefab` 的交互控件使用
- `Assets/Scripts/Sign/Legacy/SignCtrlHoverHitbox.cs`
  - 仍作为 hover/click 透明命中层转发器使用
