# Contracting.Stamp 模块事实

最后更新时间：2026-03-21（Asia/Shanghai）

## 1. 脚本清单（代码事实）

- `Assets/Scripts/SignMiniGame/Stamp/StampPanel.cs`
- `Assets/Scripts/SignMiniGame/Stamp/StampQuickTestLauncher.cs`
- `Assets/Scripts/SignMiniGame/Stamp/StampGuideTag.cs`

## 2. 面板职责事实

- `StampPanel : UIPanel`
- 输入：`StampPanelData`
  - `ClientId`
  - `TutorialMode`
  - `HasVerifyDebuff`
  - `RuntimeConfig`
  - `ClientConfig`
- 输出：`StampResultPayload`

## 3. 状态机事实

- `ChooseType`
- `PrepareStamp`
- `ChargeLoop`
- `HitWindow`
- `Resolve`
- `Completed`

## 4. 核心判定事实

- 两段式判定：
  - 类型判定：`selectedType == CorrectStampType`
  - 时机判定：`EvaluateTiming(currentChargeNormalized)`
- 时机判定区间来自 `RuntimeConfig`：
  - `PerfectWindowStart/End`
  - `NormalWindowPadding`
- 时机不命中时返回 `Failed`，并根据与窗口距离判断 `lightFail`。
- 若类型错误，最终按失败路径处理。

## 5. Verify Debuff 事实

- `HasVerifyDebuff=true` 时，蓄力阶段会叠加抖动干扰（振幅/次数来自配置）。

## 6. 提交与全局连接事实

- 面板完成后回调 `StampResultPayload`（`WasFallback=false`）：
  - `SelectedStampType`
  - `TimingResult`
  - `HitNormalizedTime`
  - `TypeCorrect`
  - `HasVerifyDebuff`
- 对话层提交 `SubmitStampSelectionResultCommand` 后会更新：
  - `RouteStampType`
  - `RouteStampTimingResult`
  - `Satisfaction/SignMistake`

## 7. QuickTest 与 GuideTag 事实

- `StampQuickTestLauncher`
  - 支持配置 `clientId/tutorial/verifyDebuff/基线状态`
  - 热键重开默认 `T`
  - 运行超时日志保护
- `StampGuideTag` 是空组件，用于引导标签定位。
