# Contracting.RuneVerify 模块事实

最后更新时间：2026-03-21（Asia/Shanghai）

## 1. 脚本清单（代码事实）

- `Assets/Scripts/SignMiniGame/RuneVerify/RuneVerifyPanel.cs`
- `Assets/Scripts/SignMiniGame/RuneVerify/RuneVerifyQuickTestLauncher.cs`
- `Assets/Scripts/SignMiniGame/RuneVerify/RuneVerifyGuideTag.cs`

## 2. 面板职责事实

- `RuneVerifyPanel : UIPanel`
- 输入数据：`RuneVerifyPanelData`
  - `RuntimeConfig`
  - `RuntimeSeed`
- 输出数据：`RuneVerifyResultPayload`

## 3. 状态机事实

- `SpawnGrid`
- `Countdown`
- `Hunting`
- `ResultSuccess`
- `ResultFail`
- `Completed`

## 4. 触发与网格生成事实

- 是否触发由上层 `ITCDialoguePanel` 决定：
  - 使用 `RuneVerifyConfig.TriggerProbability`
  - 用 `FixedRandomSeed` 或 day/client 混合种子计算随机
- 触发后面板内部会：
  - 按 `GridWidth * GridHeight` 建格
  - 按 `DistortedCount` 随机生成扭曲索引集合
  - 进入限时搜索

## 5. 判定事实

- 时限：`TimeLimitSeconds`（含最后一秒脉冲提示 `FinalSecondPulseRate`）。
- 玩家点击扭曲格累计 `FoundCount`。
- `FoundCount >= DistortedCount` 则成功，否则超时失败。
- 提交 payload：
  - `Result = Success/Failed`
  - `FoundCount`
  - `DistortedCount`
  - `Triggered = true`
  - `WasTimeoutFallback = false`
  - `RandomSeed = activeSeed`

## 6. 与全局流程连接事实

- 对话层先发 `BeginRuneVerifyCommand(clientId, triggered, seed)`。
- 未触发时直接提交 `Skipped`，不打开面板。
- 触发时由面板回调提交 `SubmitRuneVerifyResultCommand`。
- 关键回写字段：
  - `RouteRuneVerifyResult`（success/failed/skipped）
  - `RouteRuneVerifyDebuff`（失败时 1，否则 0）

## 7. QuickTest 与 GuideTag 事实

- `RuneVerifyQuickTestLauncher`
  - 强制触发验证流程（Begin 命令传 `triggered=true`）
  - 热键重开默认 `R`
  - 超时日志保护
- `RuneVerifyGuideTag` 是空组件，仅用于引导标记。
