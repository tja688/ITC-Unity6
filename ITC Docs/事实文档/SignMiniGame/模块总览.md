# Contracting 模块总览事实

最后更新时间：2026-04-01（Asia/Shanghai）

## 1. 模块职责

- 提供签约流程的全部小游戏实现与统一状态收口。
- 通过 QFramework Command + Model 维护跨环节状态一致性。
- 通过 `ITCDialoguePanel` 与 Yarn 命令协议对接。
- 在当前重构后，承担“场景内直载小游戏 UI，可见、可改、可调”的实现职责。

## 2. 子模块目录

- `Common`：类型定义、配置模型、状态模型、全局命令
- `DocumentReview`
- `RuneTyping`
- `RuneVerify`
- `Stamp`
- `SoulCollect`
- `BeanSell`
- `Settlement`

## 3. 当前场景承载事实

- `Assets/Scenes/SignMiniGameOverlayScene.unity` 当前是签约小游戏统一叠加场景。
- 该场景当前已直接实例化以下 panel prefab：
  - `DocumentReviewPanel`
  - `RuneTypingPanel`
  - `StampPanel`
  - `SoulCollectPanel`
  - `BeanSellPanel`
  - `SettlementPanel`
  - `RuneVerifyPanel`
- `SignMiniGameOverlayScene` 中的 `SignMiniGameOverlayRoot` 挂有 `SignMiniGameSceneHost`。
- `SignMiniGameSceneHost` 当前负责：
  - 缓存上述 panel 引用
  - 首帧隐藏全部小游戏 panel
  - 在需要时调用各 panel 的 `OnOpen` / `OnClose`

## 4. 统一流程事实

- 启动阶段：`BeginXxxCommand` 写入基线状态（客户 ID、满意度、失误标记等）
- 运行阶段：对应 `XxxPanel` 负责交互和局部反馈
- 提交阶段：`SubmitXxxResultCommand` 把 payload 转换为全局状态和路由字段
- 结算阶段：`FinalizeClientContractCommand` 统一产出小费、评价等级、资金与失误累计

## 5. 当前 UI 运行事实

- 各玩法核心面板仍为 `UIPanel`。
- 但当前主运行路径已经改变：
  - 不再优先通过 `UIKit.OpenPanelAsync(..., assetBundleName: "sign_minigame_ui")` 动态打开
  - 改为由 `ITCDialoguePanel` 查找 `SignMiniGameSceneHost`
  - 再由宿主直接操作已在场景里的 panel 实例
- 结果输出仍统一使用 `OnCompleted` 回调 payload。

## 6. 与对话系统的关系事实

- `ITCDialoguePanel` 当前仍是小游戏总调度入口。
- 对应 Yarn 命令触发时，`ITCDialoguePanel` 会：
  - 读取变量并发送 BeginCommand
  - 调用 `SignMiniGameSceneHost.OpenXxx(...)`
  - 监听 `OnCompleted`
  - 发送 SubmitCommand
  - 将结果回写 Yarn 变量
- 各玩法 Panel 本身仍不直接写 Yarn 变量，也不直接承担全局状态落点。

## 7. Quick Test / 旧链路事实

- 各玩法的 `QuickTestLauncher` 仍保留在仓库中。
- 这些 Launcher 当前属于：
  - 单玩法独立验证工具
  - 旧的临时起局入口
- 它们不再是当前签约主链路的正式小游戏打开方式。

## 8. 当前与旧链路的差异事实

- 旧事实中的“小游戏主要是资源包里的动态 panel”已不再符合当前主线实现。
- 当前主线更强调：
  - 小游戏都在场景里
  - 面板可直接看到、直接调
  - 后期再考虑统一打包、简化处理
