# Contracting.DocumentReview 模块事实

最后更新时间：2026-03-21（Asia/Shanghai）

## 1. 脚本清单（代码事实）

- `Assets/Scripts/SignMiniGame/DocumentReview/DocumentReviewPanel.cs`
- `Assets/Scripts/SignMiniGame/DocumentReview/DocumentReviewQuickTestLauncher.cs`
- `Assets/Scripts/SignMiniGame/DocumentReview/DocumentReviewGuideTag.cs`

## 2. 面板职责事实

- `DocumentReviewPanel : UIPanel`
- 打开数据：`DocumentReviewPanelData`
  - 包含 `ClientConfig`、`RuntimeConfig`、`ExpectedAction`、`AllowedRejectReasons`
- 输出数据：`DocumentReviewResultPayload`

## 3. 状态机事实

- `Entering`
- `Inspecting`
- `DecisionPending`
- `RejectReasonSelecting`
- `Resolving`
- `Completed`

## 4. 判定与提交流程事实

- 热点检查数不足时，提交不会立即通过：
  - 首次点击进入“危险判定确认”（`unsafeDecisionArmed`）
  - 间隔不足 `SubmitDebounceMs` 时拒绝确认
  - 再次点击才放行
- 教学模式下，若 `TutorialForceAllHotspots=true`，必须全检才能提交。
- `Pass` 直接进入结算；`Reject` 需先选择退回理由。
- `ResolveRoutine` 结束后触发 `OnCompleted(payload)`，`WasFallback=false`。

## 5. 与全局流程连接事实

- 对话层发送：`BeginDocumentReviewCommand`
- 面板提交后发送：`SubmitDocumentReviewResultCommand`
- 结果写入：
  - `RouteDocReviewResult`
  - `Satisfaction`
  - `SignMistake`
  - `LastInspectCount`

## 6. QuickTest 事实

- `DocumentReviewQuickTestLauncher` 支持：
  - `openOnStart`
  - 热键重开（默认 `R`）
  - 运行超时检测与日志
- 快测中同样走 Begin/Submit 命令链路，不绕过正式收口逻辑。

## 7. GuideTag 事实

- `DocumentReviewGuideTag` 是空组件，仅用于引导标签定位/筛选。
