# Contracting Common 模块事实

最后更新时间：2026-03-21（Asia/Shanghai）

## 1. 子模块职责

- 定义合同玩法域内数据结构（Config、PanelData、ResultPayload、枚举）。
- 维护全局流程状态模型。
- 提供 Begin/Submit/Finalize 统一命令逻辑。
- 提供默认客户配置与规则配置。

## 3. ContractFlowStateModel 事实

### 3.1 基线状态

- `CurrentClientId`
- `BaselineSatisfaction` / `BaselineSignMistake`
- `Satisfaction` / `SignMistake`

### 3.2 各环节路由缓存（示例）

- 文书审核：`RouteDocReviewResult`, `LastInspectCount`, `DocumentReviewRunning/Completed`
- 印章：`RouteStampType`, `RouteStampTimingResult`, `LastStampHitNormalized`, `StampRunning/Completed`
- 灵魂：`RouteSoulCollectPercent`, `RouteSoulMin`, `RouteSoulMax`, `SoulCollectActualRawPercent`, `SoulCollectRunning/Completed`
- 豆罐：`RouteBeanSellResult`, `RouteBeanSoldCount`, `RouteBeanPitchType`, `BeanSellCurrentDay`, `BeanSellRunning/Completed`
- 结算：`Money`, `NumberOfSignMistake`, `GlobalSignMistake`, `RouteSettlementTip`, `RouteSettlementTier`, `RouteSettlementFinalSatisfaction`, `SettlementRunning/Completed`
- RuneTyping：`RouteQteErrorCount`, `RuneTypingGridSize`, `RuneTypingRunning/Completed`
- RuneVerify：`RouteRuneVerifyResult`, `RouteRuneVerifyDebuff`, `RuneVerifyFoundCount`, `RuneVerifyDistortedCount`, `RuneVerifySeed`, `RuneVerifyRunning/Completed`

## 4. ContractClientConfigModel 事实

### 4.1 默认规则配置

- 文书审核：`DocumentReviewConfig` 默认值（最小检查数、惩罚策略、教学强制全检等）。
- 印章：`StampConfig` 默认值（周期、完美窗、普通窗、失败惩罚）。
- 灵魂：`SoulCollectConfig` 默认值（目标区间、辅助、过低/过高策略）。
- 豆罐：`BeanSellConfig`（默认 Day2 开启、失败扣满意度、阈值判定）。
- 结算：`ContractSettlementConfig`（满意度阈值、阶层小费范围、反馈时长）。
- RuneTyping：`RuneTypingConfig`（网格、序列长度、输入节流等）。
- RuneVerify：`RuneVerifyConfig`（触发概率、网格尺寸、时限、扭曲数量等）。

### 4.2 默认客户样本（代码内建）

- 文书审核：client 1 `Emmett`，client 2 `Thomas`。
- 印章：client 1 正确类型 `Event`，client 2 正确类型 `Skill`。
- 灵魂：client 1 目标区间 40-50，client 2 60-60。
- 豆罐：client 1/2/3 有不同偏好与购买意愿。
- 结算：client 1/2 工人阶层，client 3 资产阶层。
- RuneTyping：client 1/2 有预置序列；缺省时按种子算法生成。

## 5. ContractCommands 事实

### 5.1 Begin 命令职责

- `BeginDocumentReviewCommand`
- `BeginRuneTypingCommand`
- `BeginRuneVerifyCommand`
- `BeginStampSelectionCommand`
- `BeginSoulCollectCommand`
- `BeginBeanSellCommand`
- `BeginSettlementCommand`

共同特征：写入当前客户与基线状态，设置对应环节 `Running=true, Completed=false`。

### 5.2 Submit 命令职责

- `SubmitDocumentReviewResultCommand`
- `SubmitRuneTypingResultCommand`
- `SubmitRuneVerifyResultCommand`
- `SubmitStampSelectionResultCommand`
- `SubmitSoulCollectResultCommand`
- `SubmitBeanSellResultCommand`

共同特征：读取 payload，按规则更新 `Satisfaction/SignMistake/Route*`，再设置 `Running=false, Completed=true`。

### 5.3 Finalize 命令职责

- `FinalizeClientContractCommand(day)`
  - 结算满意度 clamp。
  - 依据阶层 + day + client + satisfaction 计算小费。
  - 更新资金、签约失误累计、评价等级（good/neutral/bad）。

## 6. 变量语义映射事实（命令层）

- 文书审核路由：`passed / rejected_correct / rejected_wrong`
- 印章路由：`RouteStampType`（金钱/名利/特技/事件），`RouteStampTimingResult`（perfect/normal/failed）
- RuneVerify 路由：`success / failed / skipped`
- 豆罐路由：`success / failed / skipped`
- 结算路由：`RouteSettlementTier`（good/neutral/bad）
