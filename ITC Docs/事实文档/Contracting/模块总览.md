# Contracting 模块总览事实

最后更新时间：2026-03-21（Asia/Shanghai）

## 1. 模块职责

- 提供签约流程的全部小游戏实现与统一状态收口。
- 通过 QFramework Command + Model 维护跨环节状态一致性。
- 通过 `ITCDialoguePanel` 与 Yarn 命令协议对接。

## 2. 子模块目录

- `Common`：类型定义、配置模型、状态模型、全局命令。
- `DocumentReview`
- `RuneTyping`
- `RuneVerify`
- `Stamp`
- `SoulCollect`
- `BeanSell`
- `Settlement`

## 3. 统一流程事实

- 启动阶段：`BeginXxxCommand` 写入基线状态（客户ID、满意度、失误标记等）。
- 运行阶段：对应 `XxxPanel` 负责交互和局部反馈。
- 提交阶段：`SubmitXxxResultCommand` 把 payload 转换为全局状态和路由字段。
- 结算阶段：`FinalizeClientContractCommand` 统一产出小费、评价等级、资金与失误累计。

## 4. 统一 UI 运行事实

- 各面板均为 `UIPanel`，大多在 `UILevel.PopUI` 打开。
- 面板数据均通过 `UIPanelData` 子类传入。
- 结果输出统一使用 `OnCompleted` 回调 payload。
- 每个玩法都有 `QuickTestLauncher`（独立起局 + 超时日志 + EventSystem 兜底）。

## 5. 统一状态落点

- 统一落在 `ContractFlowStateModel`（详见 `Common/模块事实.md`）。
- Yarn 回写动作由 `ITCDialoguePanel` 统一执行，不在单玩法 Panel 内直接写变量。
