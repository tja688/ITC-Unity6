最后更新时间：2026-04-01（Asia/Shanghai）

## 1. 本次建模范围（按你的要求）

- 主事实源：`Assets/Scripts/**` 的自研业务代码。
- 辅助事实源：`Assets/Scenes/**`、`ProjectSettings/EditorBuildSettings.asset`、`Assets/Prefabs/UI/**`。

- 明确排除：
  - `Assets/Scripts/Hedium/**`
  - `Assets/Tests/**`

## 2. 当前重构主旨（代码与场景已落地）

- 当前项目已从“偏 Web 登录 / AB 包 / 异步流式 UI 打开”的组织方式，切到“所见即所得、重可改、重可调、重 demo 演示”的交付方式。
- 当前主线目标不是工业化完美架构，而是：
  - 面板直接落场景
  - 游戏内容直接可见可调
  - 对话与签约小游戏拆成独立场景
  - 通过场景叠加承载演示流程
- 现阶段仍保留部分 ResKit / UIKit / AssetBundle 兼容代码，但主流程已经不再把它们作为唯一入口。

## 6. 全局入口与运行链路事实

- 应用架构根仍为 `MainMenuApp : Architecture<MainMenuApp>`。
- `MainMenuApp` 仍注册三个核心 Model：
  - `MainMenuStateModel`
  - `SignMiniGameFlowStateModel`
  - `SignMiniGameClientConfigModel`
- 当前入口链路按代码实现为：
  - `MainMenuFlowLauncher`：不再初始化 ResKit / UIKit，仅标记逻辑 ready、打开场景内主菜单，并按配置可直接切到 `SignScene`。
  - `RequestOpenDialoguePanelCommand`：不再打开 `dialogue_ui` 包，而是直接 `LoadScene("SignScene", Single)`。
  - `SignSceneOverlayLoader`：按代码负责把 `DialogueScene` / `SignMiniGameOverlayScene` 作为叠加场景拉起。
  - `SignRuntimeSceneBootstrap`：提供脱离场景对象生命周期的运行时兜底，确保签约主链的叠场景准备逻辑存在第二条入口。
  - `SignSceneDialogueLauncher`：在对话叠加场景内启动 `DialogueRunner`，并在启动前再次检查所需叠加场景是否已加载。

## 7. 对话与小游戏命令桥接事实

- 对话统一桥接控制器仍为 `ITCDialoguePanel`。
- Yarn 命令总表仍包含：
  - 视觉与场景：`itc_bg`、`itc_npc_main`、`itc_npc_avatar`、`itc_pc_avatar`、`itc_npc_main_hide`、`itc_npc_avatar_hide`、`itc_pc_avatar_hide`、`itc_load_scene`
  - 签约小游戏：`itc_doc_review`、`itc_rune_typing`、`itc_rune_verify`、`itc_stamp_select`、`itc_soul_collect`、`itc_bean_sell`、`itc_settlement`
  - Sign 对话扩展：`itc_sign_npc_enter`、`itc_sign_npc_exit`、`itc_sign_role`
- 当前小游戏命令桥接方式已经改变：
  - 不再通过 `UIKit.OpenPanelAsync<...>(assetBundleName: "sign_minigame_ui")` 作为主路径
  - 改为通过 `SignMiniGameSceneHost` 打开/关闭已在 `SignMiniGameOverlayScene` 中落地的场景内面板

## 8. 视觉资源解析事实

- `DialogueVisualCatalog` 当前已支持直接场景/资产引用：
  - `DialogueSpriteRef.directSprite`
  - `DialogueVisualCatalog.missingSprite`
- `DialogueSpriteProvider` 的加载优先级当前为：
  - 优先 `directSprite`
  - 其次缓存
  - Editor Simulation 的 `editorAssetPath`
  - 最后才是 ResKit / AssetBundle 路径

## 9. 流程收口事实

- 每个小游戏面板仍只产出局部结果 payload。
- 全局结果仍统一落到 `ContractCommands` 与 `SignMiniGameFlowStateModel`。
- `ITCDialoguePanel` 仍负责三件事：
  - 发起具体小游戏
  - 监听完成回调并提交结果命令
  - 把模型结果回写 Yarn 变量
- 现阶段保留 fallback / timeout 兜底逻辑，避免对话主流程卡死。

## 10. 当前已知取舍事实

- 仓库中仍保留部分旧 AB / ResKit / UIKit / QuickTestLauncher 代码，作为兼容层或单玩法独立验证工具。
- 当前主交付路径已经不再以“严格 AB 包组织”和“异步动态打开 UI”为第一优先级。
- 当前事实判断以“场景直载、可见可调、演示优先”的链路为准。
