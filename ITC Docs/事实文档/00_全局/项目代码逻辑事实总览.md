## 3. 全局架构事实

- 应用架构根为 `MainMenuApp : Architecture<MainMenuApp>`。
- `MainMenuApp` 注册了三个核心 Model：
  - `MainMenuStateModel`
  - `SignMiniGameFlowStateModel`
  - `SignMiniGameClientConfigModel`
- 入口场景逻辑：
  - `MainMenuFlowLauncher`：初始化 ResKit，打开主菜单，按配置可自动进入对话。
  - `DialogueSceneFlowLauncher`：初始化 ResKit，按配置直接打开 `ITCDialoguePanel`。
- 对话主控制器：
  - `ITCDialoguePanel` 统一注册 Yarn 命令、桥接视觉与各小游戏 Panel。

## 6. 流程收口事实

- 每个小游戏的 UI Panel 只产出 payload（局部结果），不直接改全局状态。
- 全局状态由 `ContractCommands`（Begin/Submit/Finalize）统一落入 `SignMiniGameFlowStateModel`。
- `ITCDialoguePanel` 负责三件事：
  - 开启对应 Panel
  - 监听完成回调并发提交命令
  - 将模型状态回写 Yarn 变量
- 对每个小游戏都实现了“开面板超时 / 结算超时”的 fallback 兜底逻辑，避免 Yarn 主流程卡死。
