## 2. 当前实现总览

### 2.1 关键模块

1. `TALinePresenter`  
路径：`Assets/Scripts/Dialogue/TALinePresenter.cs`  
职责：接 Yarn 行，决定“走 legacy 文本呈现”还是“路由到 Sign 槽位系统”。

2. `SignDialogueSlotRuntime`  
路径：`Assets/Scripts/Dialogue/Sign/SignDialogueSlotRuntime.cs`  
职责：Sign 专属核心。管理 NPC 双槽、玩家槽、选项对齐、历史滚轮、占位小游戏遮罩、Yarn 命令接入、Runner 修正。

3. `DialogueContinueHandler`  
路径：`Assets/Scripts/Dialogue/DialogueContinueHandler.cs`  
职责：统一输入推进；增加 `SignDialogueSlotRuntime.IsContinueInputBlocked` 阻塞判定。

4. `SignDialogueTestLoopDriver`（测试场景专用）  
路径：`Assets/Tests/Test scripts/SignDialogueTestLoopDriver.cs`  
职责：TestScene 自动重启循环，保证打开即测。

5. Yarn 测试剧本  
路径：`Assets/Tests/Test dialogue/TestMinigames.yarn`  
职责：覆盖 NPC/玩家/心理活动/选项/小游戏/切 NPC 全链路。

### 2.2 运行时数据流（简版）

1. `DialogueRunner` 推进到一行。  
2. `TALinePresenter.RunLineAsync` 判断 `routeToSignSlots`。  
3. 若走 Sign 路由：调用 `SignDialogueSlotRuntime.RouteLine()`，legacy 文本层关闭。  
4. `SignDialogueSlotRuntime` 按角色类型分发：  
`NPC -> Slot1/Slot2`，`Player/Thought -> PlayerSlot1`。  
5. `DialogueContinueHandler` 每帧请求推进前先看 `IsContinueInputBlocked`：  
小游戏遮罩中或选项激活时，拦截“点空白推进”。

## 4. 对原 Dialogue 路径的侵入性修改评估

### 4.1 修改点与风险级别

| 文件 | 修改内容 | 侵入级别 | 影响范围 |
|---|---|---:|---|
| `TALinePresenter.cs` | 增加 Sign 路由分支、禁用 legacy TextAnimator/Typewriter、Sign 模式下保持 `DialoguePanel` 可见 | 中 | 仅当 `routeToSignSlots=true` 且运行时找到 `SignDialogueSlotRuntime` |
| `DialogueContinueHandler.cs` | 增加 `signDialogueSlotRuntime` 阻塞判定 | 低 | 无运行时引用时等价无影响 |
| `SignDialogueSlotRuntime.cs` | 反射重排 presenter 顺序、注册 Sign 命令、运行时强制 `allowOptionFallthrough=false`、自动启动节点、对齐/动画/历史逻辑 | 高（Sign 专属） | 挂了该组件的 Runner 与 UI |
| `TestScene.unity` | 参数覆盖与测试循环挂载 | 低 | 仅 TestScene |

### 4.2 是否会破坏原本 Dialogue 工作流

结论：默认**不会全局破坏**，但有明确边界条件。

1. 安全边界：  
- 非 Sign 场景不挂 `SignDialogueSlotRuntime`，或 `routeToSignSlots=false`，`TALinePresenter` 仍走原流程。  
- `DialogueContinueHandler` 未绑定 runtime 时，阻塞逻辑不生效。

2. 潜在破坏点（需注意）：  
- 在同一场景存在多个 `DialogueRunner` 时，`FindFirstObjectByType` 可能绑错对象。  
- `SignDialogueSlotRuntime` 会运行时修正 Runner（presenter 顺序、fallthrough），属于主动“改机”。  
- `autoStartDialogueIfIdle=true` 会自动拉起 `Start`，不适合所有场景。  
- 组件内部通过固定层级名找锚点（`纯背景/对话框遮罩/对话框1号` 等），改层级会失效。

## 5. Sign 专属行为（当前已实现）

### 5.1 Yarn 命令扩展

`SignDialogueSlotRuntime` 注册了以下命令：

1. `itc_sign_npc_enter <npcId>`：重置并切换 NPC 周期。  
2. `itc_sign_npc_exit`：隐藏 NPC 双槽。  
3. `itc_sign_role <npc/player/thought/auto>`：强制角色判定。  
4. `itc_sign_minigame <token>`：显示占位小游戏遮罩，按 `Y` 结束。

### 5.2 NPC 双槽逻辑

1. Slot1 永远显示最新句。  
2. Slot2 默认显示上一句，并允许滚轮回看历史。  
3. 鼠标移出历史区域时，Slot2 回归默认上一句。  
4. 新句到来时，执行“1号迁移到2号 + 新句延时刷新到1号”的并发动效。

### 5.3 选项阻塞逻辑

`IsOptionsBlockingContinue()` 现在只在“有激活且可交互选项”时阻塞空白推进，避免假阻塞。

## 6. 参数手册（手感调优）

参数所在脚本：`SignDialogueSlotRuntime`

| 参数 | 含义 | 建议调法 |
|---|---|---|
| `textFadeDuration` | 文本淡入淡出时长 | 文本“闪”就加大；拖沓就减小 |
| `textSlideDistance` | 文本过渡位移 | 想更“翻牌感”可略增 |
| `frameMoveDuration` | 1号到2号迁移总时长 | 迁移不明显就增大（当前 TestScene=0.52） |
| `frameFlipAngle` | 新句迁移时框体倾角 | 过大易眩晕；80~90 较明显 |
| `npcSlot1RefreshDelayRatio` | 新句刷新延迟比例（相对 `frameMoveDuration`） | 想突出“旧句先走再上新句”就增大 |
| `slot2CarryFadeFrom` | Slot2 承接动画起始透明度 | 越低越明显“接管” |
| `slot2CarryTextNudge` | Slot2 承接文本初始偏移 | 越大越有迁移感 |
| `historyScrollFlipAngle` | 滚轮翻历史时的独立翻角 | 建议小角度（12~24），防抖动 |
| `historyScrollFlipDuration` | 滚轮翻历史动画时长 | 0.10~0.18 常用 |
| `freezeHistoryHitAreaWhileBrowsing` | 浏览时是否冻结历史命中区 | 建议始终开启，防止命中区抖动 |
| `optionsPanelPadding` | 选项框尺寸相对玩家框内缩 | 过小会挤，过大可读性差 |
| `optionsPanelOffset` | 选项框相对玩家框偏移 | 用于快速调位 |
| `normalizeOptionsPanelAnchorToCenter` | 强制选项框中心锚点 | 建议开启，避免锚点导致跑偏 |

## 7. 已知风险与排障

### 7.1 常见问题与定位

1. 对话/小游戏整体不可见  
看 `DialoguePanel` 的 `CanvasGroup.alpha`，Sign 模式应保持为 `1`。

2. 选项点完后卡住  
看 `DialogueRunner` 的 `allowOptionFallthrough` 是否为 `false`；看 options 子项是否还残留 `active+interactable`。

3. 滚轮翻历史抖动  
确认 `freezeHistoryHitAreaWhileBrowsing=true`，并降低 `historyScrollFlipAngle`。

4. 迁移感不明显  
提高 `frameMoveDuration` 与 `npcSlot1RefreshDelayRatio`，并增大 `slot2CarryTextNudge`。

### 7.2 升级 Yarn/插件时回归清单

1. `ResolvePresenterList()` 反射字段是否仍是 `dialoguePresenters/dialogueViews`。  
2. `allowOptionFallthrough` 字段/属性名是否变化。  
3. `OptionItem` 类型是否仍可用于“选项激活”判定。  
4. `TALinePresenter` 在 Sign 抑制路径下是否仍不会触发 TextAnimator 空引用。  
5. 命令注册 `AddCommandHandler`/`RemoveCommandHandler` API 签名是否变化。

## 8. 解耦建议（后续升级推荐）

当前方案可用，但耦合点较多。建议分两步解耦。

### 8.1 第一步（低成本）

1. 把 `SignDialogueSlotRuntime` 的 Runner 修正行为（presenter 重排、fallthrough 关闭）搬到独立 `SignDialogueBootstrap`。  
2. `TALinePresenter` 保留通用职责，仅通过接口调用 Sign 路由（如 `ISignLineRouter`），减少直接类型耦合。  
3. 把锚点路径字符串改为可序列化引用，不依赖层级名硬编码。

### 8.2 第二步（推荐）

1. 做一套 Sign 专属 Presenter 组合：  
- `SignLinePresenter`  
- `SignContinueHandler`  
- `SignOptionsBridge`
2. 通用对话场景继续使用原 `TALinePresenter + OptionsPresenter + ContinueHandler`。  
3. Sign 场景通过独立 prefab/installer 注入，彻底和主流程分层。

## 10. 结论

当前实现已经满足签约测试场景的核心目标：  

1. Sign 双槽 + 玩家槽 + 选项阻塞 + 占位小游戏阻塞可工作。  
2. 对主 Dialogue 流程存在可控侵入，但边界依赖配置与场景挂载。  
3. 若后续要做长期维护和版本升级，建议按第 8 节进行分层解耦，避免 Sign 专属逻辑继续扩散到通用对话路径。

## 11. 独立原型测试补充

### 11.1 轻量卡片手感原型

新增了一个独立原型脚本，用于只测试场景中 `对话框1号` 的点对点手感，不依赖现有 Sign 双槽实现：

1. 脚本路径：`Assets/Tests/Test scripts/Sign面板相关测试/SignPanelCardFeelPrototype.cs`
2. 场景挂载菜单：`ITC/Tests/Setup Sign Card Feel Prototype`
3. 交互逻辑：
   - 鼠标左键：`0号` -> `1号` 弹出，随后轻微抖动两下并收平。
   - 鼠标左键再次点击：`1号` 翻落到 `-90` 度。
   - 鼠标右键：`-90` 度卡片回到 `1号` 当前场景位置，并带轻微前后摇摆与阻尼收平。
   - 鼠标右键再次点击：`1号` 垂直退场到 `0号` 位置并隐藏。

### 11.2 设计边界

1. 这是纯原型测试，不接入现有对话历史、Yarn、选项或小游戏阻塞逻辑。  
2. 目标是快速调手感，默认采用轻量缓动，不做复杂状态编排。  
3. 如果后续要把这套手感接回生产 Sign 流程，建议单独再做一次迁移评估，不直接复用原型脚本。
