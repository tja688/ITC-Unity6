# 签约场景对话组件规格（文字版设计案 v1.0）

## 0. 背景与落地方式

* 项目核心对话机由**自定义 Yarn Spinner 驱动**：所有对白/玩家对白/主角心理活动/选项，都是 Yarn 剧本里写死的对话步骤。（见技能 itc-yarn-authoring ）
* 推进方式：**统一鼠标点击推进**（见 2.1）。
* 小游戏：会弹出一个**覆盖 UI** 拦截点击，导致对话无法推进；对话系统不需要额外“冻结提示/冻结态”，只需要自然停住（见 2.4）。
* AI 落地方式：允许 AI 通过 MCP **直接探查场景**、读取现有对话框对象和素材；**场景名字不改**，你已经配好。

---

## 1. UI 组成与“槽位 Slot”定义（必须固定）

> NPC 与玩家对话框不是“独立系统”，本质都是 Yarn 对话的一种呈现形态；但为了实现双框与历史翻阅，需要明确槽位。

### 1.1 NPC 对话框槽位（3 个）

* **NPCSlot0（准备位 / 不可见）**
  用于下一句 NPC 对话的预备（隐藏、不可交互）。
* **NPCSlot1（主框 / 最新一句）**
  永远显示 **最新** NPC 台词（固定语义，不随翻历史改变）。
* **NPCSlot2（次框 / 历史窗口）**
  默认显示“上一句（最近历史）”，并且支持在鼠标滚轮操作下翻阅任意历史句子（窗口式翻牌）。

> 你的明确规则：
>
> * Slot1 永远是最新
> * Slot2 是“机械翻牌显示器”式的历史窗口

### 1.2 玩家对话框槽位（2 个）

* **PlayerSlot0（准备位 / 不可见）**
* **PlayerSlot1（主玩家框）**：同一个框，承载三类呈现：

  1. 玩家对白（需要点击推进）
  2. 主角心理活动（只展示，点击任意区域当推进即可）
  3. 选项列表（必须点选项；点外面不推进，阻塞）

---

## 2. 输入与推进规则（硬规则）

### 2.1 全局推进输入：统一鼠标点击

* 对话推进仅靠鼠标点击（无自动计时、无语音播完自动推进）。
* 默认“点击推进”是**全屏/任意区域**都可触发（除非处于选项态，见 2.3）。

### 2.2 NPC/玩家普通台词态：点击继续

* 只要当前步骤不是选项选择态，点击任意区域都视为“继续”，推进到 Yarn 下一步。

### 2.3 选项态：必须点选项，点外面无效（阻塞推进）

* 当 Yarn 给出选项时：

  * 仅点击具体选项按钮才会推进
  * 点击非选项区域（包括背景、NPC 框区域、玩家框空白）**不推进**
  * 直到选项选中 → 播放选择响应动画 → 再交回 Yarn 继续

### 2.4 小游戏覆盖 UI：自然阻塞点击

* 小游戏出现时，会有覆盖 UI 拦截鼠标点击，导致对话无法推进。
* 对话系统无需显式冻结逻辑/提示；表现为：用户点击没反应（被小游戏 UI 吃掉）。
* 小游戏结束，覆盖 UI 移除后，继续点击即可自然推进。

---

## 3. NPC 出场周期与“单 NPC 时间段”的限定（硬规则）

* 叙事结构：**一个时间段只有一个 NPC**（NPC 轮流出场，但同一段时间只会存在一个 NPC 的对话在播）。
* NPC 切换触发：跟随剧情的 **NPC 退场/出场**事件触发。
* NPC 切换时：

  * **清空重来**：清掉 NPC 历史缓存与展示（只保留当前 NPC 时间段内的全部对话历史）
  * Slot1/Slot2 重新初始化到该 NPC 的第一句/默认历史（或空）

---

## 4. NPC 对话历史：逻辑全保留 + 视觉复用（性能约束）

### 4.1 历史容量与范围

* 历史允许多句：保留“当前 NPC 时间段内的所有台词”（理论上可无限，但建议工程上设一个上限防极端剧本）。
* 历史数据**逻辑保留**：不丢弃。
* 历史展示**视觉复用**：不能为了每一句历史都实例化一个 UI 预制体堆在层级里。

### 4.2 展示窗口规则

* Slot1：永远绑定最新一句 NPC 台词（固定）。
* Slot2：一个“窗口”，默认显示“上一句”；用户在指定区域滚轮时，可以把 Slot2 显示切到任意历史句子（类似机械翻牌显示器翻到某一条）。
* 鼠标移出滚轮区域时：**Slot2 自动回归**到“正常次历史显示内容”（也就是默认上一句/最近历史那条）。

---

## 5. NPC 双框更新机制（新句到来时的动作）

当 Yarn 推进到下一句 NPC 台词（同 NPC 时间段内）时，必须发生：

1. 新句成为 `NpcLatest`，展示到 Slot1（主框）
2. 原 Slot1 显示的旧句成为“最近历史”，应成为 Slot2 的默认内容
3. Slot2 的当前“正在翻阅的历史显示”如果不是默认最近历史，也要遵循规则：

   * **逻辑上**：默认最近历史更新为旧 Slot1 那句
   * **视觉上**：如果玩家正在翻历史（slot2 显示的是更早句），建议先不要强制跳回（除非你希望强制），但鼠标移出区域时依然会回归到新的默认最近历史
     （这一点在工程实现里要明确，见最后问题 Q4）

---

## 6. 滚轮翻历史交互（Slot2 专属区域）

### 6.1 触发区域

* 有一个可交互区域，**大致等于“次对话框显示的位置”**。
* 鼠标悬停在该区域内时：

  * 滚轮上/下：切换 Slot2 显示的历史索引（向旧/向新）
  * 动画方向随滚轮方向变化（正滚顺着来，倒滚倒着来）

### 6.2 鼠标移出回归

* 鼠标离开该区域后：

  * Slot2 自动“翻回”到默认最近历史那句（上一句）
  * 回归也要走翻牌动画（建议），以符合“机械翻牌显示器”的体感

### 6.3 与小游戏/选项态的关系

* 小游戏覆盖 UI 时，通常鼠标事件也会被覆盖 UI 抢走：因此滚轮翻历史是否还能用取决于覆盖 UI 的拦截策略。
  你给的规则是“允许全部”，所以建议：

  * 覆盖 UI 仅拦截点击推进，但**不要拦截滚轮**，或让滚轮事件透传到对话区域（实现手段见 8.4）。

---

## 7. 动画规范（先能跑，再慢慢调）

### 7.1 出场动画（统一：缓动弹出 + 过冲回弹）

* 适用：NPC 对话框组入场、玩家对话框入场、选项面板出现等。
* 动画风格：先快后慢、带轻微过冲回弹。

### 7.2 退场动画（统一：直接快速缩回，干净利落）

* 适用：NPC 对话框组退场、玩家对话框退场、选项面板消失等。

### 7.3 “新句挤占”与“Slot2 翻牌/退场”同时触发

你定的规则是：**同时触发**，先按这个做，后续再打磨同步细节。

建议的可执行动作（不要求一次到位，但逻辑要一致）：

* 当新 NPC 句到来：

  1. Slot1（旧句）触发“挤占”运动到 Slot2 位置（示意：1 号框越至 2 号框位置，缓动）
  2. Slot2 同时触发翻牌/过渡动画（包括你图里的“X 轴旋转到 90 度”风格）
  3. Slot1 同时加载新句并完成自己的呈现（可用淡入/翻牌/打字等）

> 关键：动画可以先简化（比如只做位置移动 + alpha），但要把“同时触发”的结构留出来，方便你后续调成你想要的那套组合动效。

## 8. Yarn 驱动接入点（AI 实做时应该怎么挂）

> 这里按“最少改你现有架构”的方式写：对话展示系统只负责“接 Yarn 的事件 → 刷 UI”，不改场景名、不狂造对象。

### 8.1 Yarn 步骤类型识别（必须有）

当 Yarn 推进到下一步时，需要能判定当前输出属于哪类：

* NPC 台词：走 NPC Slot1/Slot2 逻辑
* 玩家台词 / 主角心理活动：走 PlayerSlot1 展示逻辑
* 选项：走 PlayerSlot1 选项模式（阻塞）
* NPC 出场/退场事件：清空 NPC 时间段历史，并触发入/退场动画

实现方式不限定：可以是自定义 Yarn Line Tag、或 YarnCommand、或自定义 DialogueView/LinePresenter 回调。

### 8.2 历史缓存结构（建议）

* `List<NpcLineData> npcHistory`：只存当前 NPC 时间段
* `int npcHistoryIndexForSlot2`：Slot2 当前浏览到的历史索引
* `int npcDefaultIndex`：默认“上一句”的索引（一般是 `npcHistory.Count - 2`，因为最新一句在 Slot1）

Slot1 永远展示 `npcHistory.Last()`。

### 8.3 视觉复用（必须做到）

* NPCSlot1、NPCSlot2 都是**固定的两个 UI 容器**（或者两个可复用的 Presenter），切换句子时只更新内容，不创建新预制体。
* 若需要翻牌效果：在容器内部做“正反面”或一个临时过渡层，但也要复用（对象池/常驻）。

### 8.4 小游戏覆盖 UI 与滚轮透传（为了满足“允许全部”）

* 覆盖 UI 需要拦截点击推进，但尽量不要拦截滚轮事件给 Slot2 区域。
* 常见做法（供 AI 选）：

  * 覆盖 UI 的 Raycast Target 只拦截 PointerClick，不拦截 Scroll（或 Scroll 事件不消费）
  * 或者 Slot2 的滚轮区域用更高优先级/独立事件系统接收滚轮（谨慎）
  * 或者覆盖 UI 只覆盖“点击区域”，不给 Slot2 那块盖住（UI 设计层面的透孔）

## 9. 状态机摘要（给 AI 的实现抓手）

### 9.1 Player（玩家框）状态

* `Hidden`（在 Slot0）
* `ShowLine`（展示玩家/心理活动台词，点击任意区域继续）
* `ShowOptions`（展示选项，必须点选项，点外不推进）
* `AnimatingIn/Out`（可选）

### 9.2 NPC（双框）状态

* `Hidden`（退场）
* `Active_Normal`（Slot1 最新 + Slot2 默认上一句）
* `Active_BrowsingHistory`（鼠标悬停在 Slot2 区域，slot2 index 可变）
* `AnimatingShift`（新句挤占+翻牌过渡）

鼠标移出 Slot2 区域：`Active_BrowsingHistory -> Active_Normal`（触发自动回归动画）

# 10. 仍需你补一口的“落地必问点”（很少，但会卡实现）

下面这些不是“设计理念”问题，而是 AI 在 MCP 探查场景时最容易卡住的工程细节。你简单回答一句话就能继续：

**Q1. Slot2 默认显示的“上一句”是严格指：**
答：
* A) 显示 `npcHistory.Count-2` 那句（最近历史）
* B) 如果上一句为空——隐藏 Slot2


**Q2. Slot2 翻历史的边界：**

* 滚到最早一句/最新可翻到哪？
答：
  * 最早：第 0 句
  * 最新：最多翻到“上一句”就停止

**Q3. 新 NPC 句到来时，如果玩家正在翻历史（Slot2 显示更早句）：**
答：
* B) 直接强制 Slot2 回到默认上一句（打断浏览+强制退出动画+锁定到完成后再恢复可翻阅历史操作）

**Q4. “滚轮区域”的精确对象：**
AI 可以探查，但你最好给一个明确锚点：
答：
* 这个区域是 Slot2 区域的单独的透明触发层，跟Slot2本体无关

**Q5. 历史容量是否需要上限（防剧本极端）：**
不需要，单个NPC历史不多
