# 01 文书审核 - 代码文档与操作说明（可直接落地）

> 适用范围：`DocumentReview` 小游戏白模与主线接入  
> 目标：保证“可独立测试、可一键运行、可读可维护、可替换资源不改判定逻辑”

---

## 1. 代码结构（本次落地）

### 1.1 业务层（QFramework）

- `Assets/Scripts/Contracting/Common/ContractFlowStateModel.cs`  
  - 记录本轮客户、检查数、文书审核结果、`Sign_mistake/satisfaction` 回写值
- `Assets/Scripts/Contracting/Common/ContractClientConfigModel.cs`  
  - 提供 Day1 客户配置（Client1/Client2 的正确判定均为 `Pass`）
- `Assets/Scripts/Contracting/Common/ContractCommands.cs`  
  - `BeginDocumentReviewCommand`：开局写作基线状态  
  - `SubmitDocumentReviewResultCommand`：统一收口判定、统一回写结果

### 1.2 UI层（Panel）

- `Assets/Scripts/Contracting/DocumentReview/DocumentReviewPanel.cs`  
  - 状态机：Entering -> Inspecting -> DecisionPending -> RejectReasonSelecting -> Resolving -> Completed  
  - 交互：热点检查、通过/退回、二次确认、理由选择、缩放  
  - 说明系统：面板内中文说明标注一键开/关
- `Assets/Scripts/Contracting/DocumentReview/DocumentReviewGuideTag.cs`  
  - 说明标注对象的统一标记组件（用于全量开关）

### 1.3 流程桥接层（Yarn）

- `Assets/Scripts/Dialogue/ITCDialoguePanel.cs`  
  - 注册命令：`<<itc_doc_review clientId>>`  
  - 命令流程：打开面板 -> 等待完成 -> 回写 `$Route_DocReviewResult/$Sign_mistake/$satisfaction` -> 关闭面板
- `Assets/Doc/ITC Doc/dialogue/ITC_YARN_DATA_TEXT_ANIM.yarn`  
  - FileCheck 节点由纯选项改为小游戏命令分支

## 2. 一键测试启动器（必须）

### 2.1 一键运行入口（编辑器菜单）

- 菜单：`ITC/Contracting/一键运行 01文书审核全流程测试`
- 实现文件：`Assets/Editor/Contracting/DocumentReviewQuickTestTools.cs`

执行后行为：

1. 自动补齐相机与测试启动器对象（如缺失）
2. 自动配置 `DocumentReviewQuickTestLauncher`
3. 自动进入 Play
4. 自动打开并跑完 01 文书审核全流程（打开 -> 交互 -> 提交 -> 回写 -> 关闭）
5. 启动器为运行时临时对象，不写入场景文件

停止入口：

- 菜单：`ITC/Contracting/一键停止 01文书审核全流程测试`

### 2.2 场景内快速复测

- 组件：`Assets/Scripts/Contracting/DocumentReview/DocumentReviewQuickTestLauncher.cs`
- 默认 `openOnStart=true`，进入 Play 即自动开局
- 热键 `R`：重复开启下一轮测试
- 具备超时保护：超时会报错，避免“卡住但误以为通过”

## 3. 白模产物与元素说明（对应对象）

### 3.1 白模 Prefab

- `Assets/Prefabs/UI/DocumentReviewPanel.prefab`
- AB：`contracting_ui`
- 生成器菜单：`ITC/Contracting/重建 01文书审核 白模Prefab`
- 生成器脚本：`Assets/Editor/Contracting/DocumentReviewPanelPrefabBuilder.cs`
- 字体强制要求（所有可见文字）：
  - `Assets/Arts/Fronts/WenQuanYi Bitmap Song 16px SDF.asset`

### 3.2 关键对象与用途（运行时对象名）

- `DocumentArea`：文书主区域（米黄色）
- `Hotspot_Seal`：印章检查热点
- `Hotspot_Ink`：墨迹检查热点
- `Hotspot_Date`：日期检查热点
- `Hotspot_Content`：条款检查热点
- `PassButton`：通过并提交
- `RejectButton`：退回并选理由
- `ZoomButton`：文档缩放切换
- `RejectReasons`：退回理由面板
- `StatusText`：状态/反馈文本
- `GuideToggleButton`：说明系统开关（说明：开/关）

## 4. 面板内中文说明系统（必须内嵌）

### 4.1 约束

- 所有说明文字均为中文
- 说明对象嵌在产物内（Prefab 内）
- 说明对象跟随被解释元素（挂在元素层级下）
- 说明支持一键开/关（`GuideToggleButton`）

### 4.2 覆盖范围

- 操作总说明
- 文书区说明
- 各热点说明
- 通过/退回/缩放按钮说明
- 退回理由面板及各理由项说明
- 状态文本说明

## 5. 落地操作步骤（给后续开发）

1. 先执行 `ITC/Contracting/重建 01文书审核 白模Prefab`，确保白模与标注为最新。  
2. 执行 `ITC/Contracting/一键运行 01文书审核全流程测试`，确认流程可完整跑通。  
3. 通过后再替换正式美术资源；禁止在换资源时修改判定流程代码。  
4. 资源替换完成后，重复第 2 步回归。
