# 05 灵魂收取分割（SoulCollect）设计与落地说明

## 第一部分：落地设计

### 1. 定位与边界

- 流程位置：盖章完成后，客户离场前
- 玩法目标：按契约份额完成分割，形成“多收降满意、少收记失误”的高价值判定
- 当前 Yarn 现状：
  - Client1：`Route_SoulMin=40`, `Route_SoulMax=50`
  - Client2：`Route_SoulMin=60`, `Route_SoulMax=60`

注意：总设计案与旧脚本在阈值描述有出入，实施时应“数据驱动优先”。

---

### 2. 面板入口与输出

- Panel：`SoulCollectPanel : UIPanel`
- 命令：`<<itc_soul_collect clientId targetPercent>>`
- 输入：`targetPercent`, `minPercent`, `maxPercent`, `tolerance`, `soulVisualTheme`
- 输出：
  - `$Route_SoulCollectPercent`
  - `$Route_SoulMin`
  - `$Route_SoulMax`

---

### 3. 交互状态机

- `SoulReveal`
- `Aiming`
- `PreviewPercent`
- `ConfirmSplit`
- `Resolve`
- `Completed`

关键约束：

- 玩家未按确认前可反复调整
- 一旦确认立即锁输入，防重复提交

---

### 4. 节奏与手感

#### 4.1 单局时长

- 新手：15-28s
- 熟练：8-16s

#### 4.2 操作手感参数

- 分割线拖拽阻尼：`0.08-0.12`
- 百分比刷新频率：`20Hz`（无需每帧）
- 确认后分裂动画：`0.45s`
- 分裂后结算停留：`0.6s`

#### 4.3 手感细节

- 分割线接近目标区间时，线条发光增强（帮助形成“接近正确”的触觉感）
- 超出上限区域渲染血红过载提示
- 低于下限区域渲染灰化损失提示

---

### 5. 判定规则与写回

- `actual < min` -> `Sign_mistake=1`
- `actual > max` -> `satisfaction-1`
- `min <= actual <= max` -> 正常通过

建议保留 `actualRawFloat`（内部日志）用于调手感，不写 Yarn。

---

### 6. 可配置项（SO）

`SoulCollectConfig`：

- `targetPercent`
- `minPercent`
- `maxPercent`
- `aimAssistRadius`
- `dragDamping`
- `splitAnimDuration`
- `tooLowAsMistake`
- `tooHighSatisfactionPenalty`
- `showTargetHintInTutorial`

客户维度：

- `soulColor`
- `revealFxKey`
- `voiceReactionKey`

### 8. UIKit/ResKit/WebGL 约束

- 分割预览不要用高频网格重算，采用简化几何比率计算
- 灵魂光效粒子提供低配档（WebGL移动端浏览器）
- 面板关闭后释放特效实例引用，避免跨客户残留

---

### 9. 独立测试（白模）

白模对象：

- 中央圆形“灵魂球”
- 可拖拽分割线
- 实时百分比文本
- `Company` 与 `Client` 双侧标签

验收：

1. Client1 区间40-50下，45为通过，30为少收失误，60为多收降满意
2. Client2 区间60-60下，仅60通过
3. 连续拖拽时百分比显示稳定，不抖动
4. 多次开关面板不会继承上局分割位置

---

### 10. 与上下游接口

- 上游：读取 Stamp 结果，不依赖其视觉对象
- 下游：写完变量后进入 `PostContract/结算` 或 Day2+ 推销分支
